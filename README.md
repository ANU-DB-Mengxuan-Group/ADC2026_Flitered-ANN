# Query-aware Routing for Filtered Approximate Nearest Neighbors Search

Code release accompanying the CIKM 2026 submission **"Query-aware Routing for Filtered Approximate Nearest Neighbors Search"**. The paper proposes a per-query ML router that, given a vector query and a discrete attribute predicate, picks the most suitable filtered ANN method and configuration on the fly. The router is trained on six real-world corpora and evaluated on a separate cohort of five mid-scale validation datasets (yahoo800k, dbpedia560k, and three synthetic-label corpora) for out-of-distribution generalization.

> **Anonymization.** Author / supervisor / institutional metadata has been removed for double-blind review. Once the paper is accepted we will restore attribution and add a `CITATION.cff`.

## Quick start

1. **Get the datasets.** Raw vectors and labels for all named datasets can be downloaded from the [Hugging Face bundle](https://huggingface.co/datasets/ffa500/filterbenchmark) that ships with the FANNS benchmark. The five V2 validation datasets used by the paper (`synth_192d`, `synth_512d`, `synth_768d_hc`, `yahoo800k`, `dbpedia560k`) are produced by the scripts in `analysis/`. Full per-dataset details: [`DATASETS.md`](./DATASETS.md).
2. **Build each method's index.** Each top-level method directory has a self-contained `README.md` documenting its build (typically `cmake -B build && make -C build -j`). Compiled binaries, pre-built indices, and large synthetic-label files are intentionally not shipped to keep the repository lightweight; they are all regenerable from the source plus the scripts here. The full list of files not shipped is in the next section.
3. **Reproduce the routing experiments.** The router pipeline has five stages — per-query recall collection, feature build, training, evaluation, online inference + latency — documented end-to-end in [`analysis/ml_router/README.md`](./analysis/ml_router/README.md). That README is the entry point for anyone reproducing the paper's headline numbers.

## Repository Layout and Data Regeneration

To keep the repository lightweight, this public release does **not** ship the following classes of files. They are all regenerable from raw data plus the scripts in this repo:

- **Pre-built indices** (`*/data/indices/`, `*.bin` graph files, HNSW indices under `faiss/data/`): rebuild from each method's build script. See per-method `README.md` for build commands.
- **Synthetic labels** for the Fixed-EQ setting (`*/synthetic_labels/yfcc/`, etc.): regenerate via `generate_acorn_synthetic_labels.py`, `generate_acorn_groundtruth.py`, and the matching CAPS / NHQ generators.
- **Per-query result CSVs** (`analysis/ml_router/perquery_recall/*.csv`): regenerated by the per-method orchestrators in `analysis/ml_router/run_perquery_*.py`. Each orchestrator writes per-query top-$k$ IDs and recall@10 to CSV.
- **ML routing intermediate data** (`analysis/ml_router/ml_*.csv`, `analysis/ml_router/centroid_features_*.csv`, `analysis/ml_router/master_per_query.pkl`): regenerated by `analysis/ml_router/build_ml_training_data.py`, `analysis/ml_router/build_ml_validation_data.py`, and `analysis/ml_router/merge_per_query.py` once per-query CSVs are produced.
- **ML routing prediction outputs** (`analysis/ml_router/results/*/full_train_val_predictions_*.csv`): regenerated by `analysis/run_v2_ml_prep_*.sh` / `analysis/ml_router/evaluate_v2_routing.py`.
- **Compiled binaries** (`CAPS/src/libfaiss.a`, `faiss/tutorial/cpp/*_HNSW_index_static`, etc.): produced by each subproject's build (`make` or `cmake`).
- **Third-party paper PDFs** under `reference/`: not redistributable; cite the originals.
- **SLURM job logs** under `logs/`: cluster-specific runtime artifacts.

Cluster paths in the shell scripts (e.g., `~/benchmarks/...`, hostnames like `weirdo`) are kept as-is for transparency, since they document the actual experimental setup used to produce the paper's numbers. Replace them with your own paths when reproducing.

A typical reproduction pipeline is: download raw vectors and labels from the Hugging Face link above, run each method's build + search scripts (per-method `README.md`), then run the five-stage ML routing pipeline documented in [`analysis/ml_router/README.md`](./analysis/ml_router/README.md) (per-query recall collection → feature build → train → evaluate → online + latency). The ML router pipeline self-contains every script needed to reproduce the paper's routing experiments.

## Brute-force ground truth

Ground-truth top-10 IDs for every (dataset, scenario) pair are produced by the brute-force tool under `UNG-dev/`. After building UNG-dev (see its README), an example invocation for the toy `words` dataset is:

```bash
cd UNG-dev/build
./tools/compute_groundtruth \
    --data_type float --dist_fn L2 \
    --base_bin_file ../data/words/words_base.bin \
    --query_bin_file ../data/words/words_query_and.bin \
    --base_label_file ../data/words/label_base.txt \
    --query_label_file ../data/words/words_query_and.txt \
    --gt_file ../data/words/words_gt_and.bin \
    --scenario containment --K 10 --num_threads 16
```

Replace `containment` with `overlap` or `equality` for the other two scenarios. Each dataset is available in `*.fvecs` and `*.bin` formats; conversion details are in `UNG-dev/README.md`. Also see <https://github.com/YZ-Cai/Unified-Navigating-Graph> for the upstream environment setup.
